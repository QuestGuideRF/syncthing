# Syncthing

Краткое описание: Syncthing - открытая система синхронизации файлов между устройствами. Она работает без центрального сервера: устройства обмениваются данными напрямую, а управление выполняется через локальный веб-интерфейс. В этой версии русский язык выбран как язык веб-интерфейса по умолчанию.

## ✨ Возможности

- Синхронизация папок между несколькими устройствами.
- Децентрализованная архитектура без обязательного облачного сервера.
- Веб-интерфейс для управления устройствами, папками и состоянием синхронизации.
- Шифрование соединений между узлами.
- Версионирование файлов и гибкие правила игнорирования.
- Сервисные компоненты для обнаружения, ретрансляции и инфраструктуры.
- Русская локализация веб-интерфейса уже присутствует в `gui/default/assets/lang/lang-ru.json`.

## 🛠 Использование

После запуска откройте веб-интерфейс Syncthing в браузере. Обычно он доступен локально по адресу `http://127.0.0.1:8384`. Добавьте удаленное устройство, выберите папку для синхронизации и подтвердите обмен на втором устройстве.

Дополнительные бинарные цели собираются тем же скриптом:

```bash
go run build.go build syncthing
go run build.go build stdiscosrv
go run build.go build strelaysrv
```

## Запуск в Docker

Контейнер `syncthing/syncthing` хранит конфигурацию и файлы в `/var/syncthing`. Смонтируйте постоянный том. `PUID` и `PGID` задают пользователя и группу (по умолчанию 1000), `UMASK` — права новых файлов, `PCAP` — дополнительные capabilities без запуска процесса от root.

~~~yaml
services:
  syncthing:
    image: syncthing/syncthing
    hostname: my-syncthing
    network_mode: host
    environment:
      PUID: "1000"
      PGID: "1000"
      STGUIADDRESS: ""
    volumes:
      - ./syncthing-data:/var/syncthing
    restart: unless-stopped
~~~

В режиме host Syncthing видит адреса локальной сети для обнаружения устройств. С пустым `STGUIADDRESS` используется адрес из конфигурации Syncthing, обычно `127.0.0.1:8384`. Если интерфейс доступен с других машин, настройте аутентификацию и TLS. Для проверки контейнера есть маршрут `/rest/noauth/health`.

## Автозапуск и системная интеграция

| Среда | Что использовать |
| --- | --- |
| systemd | В `etc/linux-systemd/` есть варианты для системного и пользовательского сервисов. |
| runit | Настройте пользователя, домашний каталог и исполняемый файл в `run`, затем разместите сценарий с каталогом `log` в `/etc/service/syncthing`. |
| Upstart | Скопируйте пользовательский вариант в `~/.config/upstart/` либо системный в `/etc/init/`. Системную службу можно запустить командой `sudo initctl start syncthing`. |
| Linux с XDG | Файлы `.desktop` можно разместить в `~/.local/share/applications` или `/usr/local/share/applications`. Для запуска при входе используйте `syncthing-start.desktop` в `~/.config/autostart`. |
| FreeBSD | Установите бинарник в `/usr/local/bin`, сценарий в `/usr/local/etc/rc.d/syncthing` и задайте `syncthing_enable=YES` в `rc.conf`. Сценарий также поддерживает `syncthing_home`, `syncthing_log_file`, `syncthing_user` и `syncthing_group`. |
| macOS | Укажите своего пользователя и путь к бинарнику в `etc/macos-launchd/syncthing.plist` и установите plist в `~/Library/LaunchAgents`. Журналы находятся в `~/Library/Logs/Syncthing.log` и `Syncthing-Error.log`. |
| Solaris | Исправьте имя пользователя и домашний каталог в `etc/solaris-smf/syncthing.xml` и импортируйте манифест через `svccfg import syncthing.xml`. |

Профили UFW находятся в `etc/firewall-ufw/`. После установки профилей обновите их через `sudo ufw app update syncthing` и разрешите профиль `syncthing` для соединений. Профиль `syncthing-gui` нужен лишь при намеренном открытии интерфейса в доверенной сети. Примеры sysctl находятся в `etc/linux-sysctl/`, применение загружаемых настроек выполняется командой `sudo sysctl -q --system`. В Debian-пакете соответствующие конфигурации уже поставляются.

## Разработка, переводы и выпуски

- При сообщении об ошибке указывайте версию, окружение, минимальный сценарий и относящиеся к нему строки журнала без секретов.
- Каталог `meta/` содержит проверки формы и соглашений исходного кода. `internal/db/sqlite/sql/schema/` описывает актуальную схему SQLite и выполняется в алфавитно-цифровом порядке при запуске. Имя файла миграции в `migrations/` начинается с номера целевой версии. Новая база получает актуальную схему сразу.
- Переводы интерфейса поддерживаются в [Weblate](https://hosted.weblate.org/projects/syncthing/). Файлы в `gui/default/assets/lang/` генерируются.
- При подготовке изменений применяйте соглашения Go и запускайте существующие тесты. Подтверждение авторства вклада (DCO) оформляется через `git commit -s`. Правила общения описаны в [кодексе поведения](CONDUCT.md).
- Скрипт выпуска читает заметки `relnotes/vN.N.N.md`, `relnotes/vN.N.md` и `relnotes/vN.md`. Файл новой версии начинается с заголовка второго уровня. Заметки могут включаться и в выпуск-кандидат.
- Страницы в `man/` генерируются из [исходников документации Syncthing](https://github.com/syncthing/docs) и входят в системные пакеты. `stdiscosrv` отвечает за глобальное обнаружение, `strelaysrv` — за ретрансляцию, `strelaypoolsrv` — за реестр публичных ретрансляторов.

Приоритеты Syncthing — целостность данных, безопасность соединений, простой запуск и автоматическая непрерывная синхронизация между устройствами.
